## What is Sajon?

Sajon is a **declarative infrastructure language** and compiler. You describe your cloud resources in a simple `.saj` file — Sajon compiles it and provisions real infrastructure on **Neon, Supabase, and AWS** — automatically.

No DevOps knowledge required. No manual dashboards. No copy-pasting connection strings.

```ruby
# app.saj — this is ALL you write

RESOURCE user_db {
    provider: "supabase"
    region:   "ap-south-1"
    SCHEMA {
        table:  "users"
        fields: ["id:int", "name:string", "email:string", "created_at:timestamp"]
    }
}
```

```bash
sajon up
```

```
✔ Supabase project created
✔ Table 'users' auto-migrated in live database
✔ sajon.env written — DATABASE_URL ready for your app
✔ docker-compose.yml generated for local development
```

**That's it. Your cloud is live.**

## Features

| Feature | Description |
|---|---|
| 🗣️ **Custom Language** | Write `.saj` files — a clean, readable DSL purpose-built for cloud infrastructure |
| ☁️ **Multi-Cloud** | Provision Neon Postgres, Supabase, AWS RDS/EC2/S3 from one file |
| 🗄️ **Auto Schema Migration** | Define tables in plain English — Sajon writes and executes the SQL |
| 🔒 **State Management** | `sajon.lock` tracks what's live — idempotent like Terraform |
| 🛡️ **Orphan Guard** | Prevents accidental data loss when resources are renamed |
| 📄 **Auto `.env` Injection** | Connection strings auto-written to `sajon.env` after deploy |
| 🔄 **CI/CD Generator** | `sajon ci github` creates a full GitHub Actions pipeline instantly |
| 🏠 **Local Dev** | `docker-compose.yml` auto-generated for local database development |
| ☁️ **Remote State** | S3-backed `sajon.lock` for multi-developer team sync |
| 🔐 **Secret Redaction** | Passwords never appear in terminal output |

## Quick Start

### 1. Create your infrastructure file

```ruby
# app.saj

RESOURCE my_database {
    provider: "supabase"
    region:   "us-east-1"
    SCHEMA {
        table:  "users"
        fields: ["id:int", "name:string", "email:string"]
    }
}

ENDPOINT GET "/health" {
    RETURN "OK"
}
```

### 2. Set your credentials

```bash
# Supabase (get from: supabase.com/dashboard/account/tokens)
export SUPABASE_ACCESS_TOKEN="your_token_here"

# Neon (get from: console.neon.tech/app/settings/api-keys)
export NEON_API_KEY="your_key_here"

# Windows PowerShell:
$env:SUPABASE_ACCESS_TOKEN="your_token_here"
```

### 3. Deploy

```bash
# Preview what will happen (no API calls made)
sajon plan

# Deploy to cloud
sajon up

# Tear everything down
sajon down
```

### 4. Use your credentials in your app

After `sajon up`, a `sajon.env` file is auto-created:

```env
# Auto-generated by Sajon CLI
SUPABASE_DATABASE_URL_MY_DATABASE="postgresql://postgres:pass@db.ref.supabase.co/postgres"
SUPABASE_URL_MY_DATABASE="https://ref.supabase.co"
```

Load it in your app:
```javascript
// Node.js
require('dotenv').config({ path: 'sajon.env' })
const db = new Pool({ connectionString: process.env.SUPABASE_DATABASE_URL_MY_DATABASE })
```

```python
# Python
from dotenv import load_dotenv
load_dotenv('sajon.env')
```

## CLI Commands

```
sajon up [file.saj] [--force]    Compile + provision cloud infrastructure
sajon plan [file.saj]            Dry-run — preview what 'up' will do (no API calls)
sajon down [--force]             Destroy all active cloud resources
sajon ci github [file.saj]       Generate GitHub Actions CI/CD workflow
sajon version                    Show compiler version
sajon help                       Show help
```

## .saj Language Reference

### DATABASE / RESOURCE Block

```ruby
RESOURCE my_db {
    provider: "supabase"    # supabase | neon | aws | postgres
    region:   "us-east-1"
    SCHEMA {
        table:  "users"
        fields: [
            "id:int",           # → SERIAL PRIMARY KEY
            "name:string",      # → VARCHAR(255)
            "bio:text",         # → TEXT
            "score:float",      # → NUMERIC(10,2)
            "active:bool",      # → BOOLEAN DEFAULT TRUE
            "joined:timestamp", # → TIMESTAMP DEFAULT NOW()
            "token:uuid"        # → UUID DEFAULT gen_random_uuid()
        ]
    }
}
```

### SERVER Block (AWS EC2)

```ruby
SERVER api_server {
    provider:      "aws"
    instance_type: "t3.medium"
    ami:           "ami-0c55b159cbfafe1f0"
    region:        "us-east-1"
}
```

### STORAGE Block (AWS S3)

```ruby
STORAGE media_bucket {
    provider: "aws"
    bucket:   "my-app-media"
    region:   "us-east-1"
}
```

### ENV Block

```ruby
ENV production {
    APP_ENV:   "production"
    LOG_LEVEL: "info"
}
```

### ENDPOINT Block

```ruby
ENDPOINT POST "/users" {
    RETURN "Created"
}
```

### WORKER Block

```ruby
WORKER email_sender {
    queue:       "emails"
    concurrency: 5
}
```

## CI/CD — Zero Config Deploy

Generate a complete GitHub Actions pipeline in one command:

```bash
sajon ci github
```

This creates `.github/workflows/sajon-deploy.yml` which:
- Runs `sajon plan` on every **Pull Request** (dry-run, no cloud calls)
- Runs `sajon up` on every **push to main** (live deploy)
- Saves `sajon.env` and `sajon.lock` as GitHub artifacts

Then add your cloud tokens as **GitHub Repository Secrets** and push. Done.

## How Sajon Works

```
.saj file
    │
    ▼
①  Lexer          →  Tokenises source (handles whitespace, CRLF, edge cases)
    │
    ▼
②  Parser         →  Recursive-descent parser builds typed AST
    │
    ▼
③  AST Dump       →  Human-readable tree printed to terminal
    │
    ▼
④  Local Emit     →  Generates docker-compose.yml for local dev
    │
    ▼
⑤a Neon Emitter   →  Provisions Neon Serverless Postgres (if NEON_API_KEY set)
⑤b AWS Emitter    →  Provisions RDS / EC2 / S3 (if AWS keys set)
⑤c Supabase Emit  →  Provisions Supabase project + runs migrations
⑤d .env Injector  →  Writes sajon.env with all connection strings
    │
    ▼
⑥  Docker Compose →  Runs docker compose up -d (local containers)
```

## State Management

Sajon tracks what it creates in `sajon.lock`:

```json
{
  "resources": {
    "user_db": {
      "provider": "supabase",
      "project_id": "abcdefghijklmnop",
      "connection_string": "postgresql://...",
      "status": "active"
    }
  }
}
```

On subsequent `sajon up` runs, existing resources are **reused** — no duplicate creation.

> ⚠️ **Add `sajon.lock` to `.gitignore`** — it contains connection strings.
> For team use, set `SAJON_REMOTE_BUCKET` to sync state via S3.

## Security

- **Secret Redaction** — Passwords/tokens never printed to terminal
- **`sajon.env` permissions** — Written with mode `0600` (owner-only read)
- **Atomic writes** — `sajon.env` and `sajon.lock` written via temp-file + rename
- **Orphan Guard** — Blocks deployment if renamed resources would cause data loss
